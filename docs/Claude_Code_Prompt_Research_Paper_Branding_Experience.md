You are working on an existing project. I want you to improve the **research-paper positioning, branding, visual identity, and overall experience** of the current application.

### 1. Research Paper Positioning — Validate the Claim

The current project is being positioned as a **“digital research paper.”**

Before changing the UI, critically evaluate whether that claim is justified.

Analyze the actual project and determine:

- What have we actually built?
- What is technically interesting or differentiated?
- What, if anything, can reasonably be considered **novelty**?
- What is simply an implementation of established techniques?
- Which parts demonstrate original engineering, experimentation, methodology, evaluation, or system design?
- Why should this be presented as a digital research paper rather than simply an AI/RAG project, technical case study, engineering report, or interactive paper?
- What makes the digital format valuable compared with a traditional static PDF/paper?

Do **not manufacture novelty** just to make the project sound more impressive.

If “research paper” is too strong a claim, identify the strongest accurate positioning based on the actual implementation.

Use the existing project as the source of truth. Inspect the codebase, architecture, evaluation methodology, metrics, documentation, and existing content before making this assessment.

### 9. Implementation Process

Before modifying anything:

1. Inspect the entire existing project.
2. Understand the current architecture and design system.
3. Understand what the project actually does.
4. Identify the existing branding and visual inconsistencies.
5. Research relevant AI/research brand systems.
6. Evaluate the current “digital research paper” positioning.
7. Establish the strongest brand direction.
8. Implement it consistently across the application.
9. Reuse existing components where appropriate.
10. Avoid unnecessary rewrites.

Do not make random design changes section-by-section.

Establish the **brand system first**, then apply it consistently.
